# Plan — Construct Mobile Inbox (Flutter)

## Classification
- **Type:** Flutter mobile app (iOS + Android)
- **Purpose:** Companion inbox app for Construct — read and act on mail, calendar events, and pulse summaries from mobile. Push notifications for urgent items.
- **Stack:** Flutter 3.x, Riverpod, Dart
- **Visual:** Match Construct desktop design language (dark/light theme, accent colors, card layouts)

---

## Decisions

| Decision | Choice |
|----------|--------|
| Platform | Flutter (iOS + Android) |
| Purpose | Mobile Inbox & Notifications |
| State management | Riverpod |
| Visual style | Match Construct Desktop |
| Auth | OAuth2 token flow against Construct API |
| Local storage | Hive or Isar for offline cache |
| Push | Firebase Cloud Messaging (FCM) |

## Screens / Pages

| # | Route | Description |
|---|-------|-------------|
| 1 | `/` | **Home / Dashboard** — unified feed of unread mail, upcoming events, recent pulse summaries. Pull-to-refresh. |
| 2 | `/mail` | **Mail Inbox** — thread list with search, unread filter. Tap → thread detail. |
| 3 | `/mail/:id` | **Thread Detail** — full message bodies, reply composer (plain text), archive/star actions. |
| 4 | `/calendar` | **Calendar** — today + upcoming 7 days. Tap event → detail with attendees, RSVP. |
| 5 | `/calendar/:id` | **Event Detail** — title, time, location, attendees, RSVP action. |
| 6 | `/pulses` | **Pulse Feed** — list of recent pulse summaries, grouped by time. |
| 7 | `/notifications` | **Notification Center** — bell items, tappable to source (mail thread, event, pulse). |
| 8 | `/settings` | **Settings** — account info, theme toggle (dark/light), notification preferences, logout. |
| 9 | `/login` | **Login** — OAuth flow, org picker if multi-org. |

**Total: 9 screens**

## Data Model (client-side)

### API Layer
All data comes from Construct's API. The Flutter app is a thin client — no local database of record.

```
ConstructApi
├── auth/          — OAuth2 token management, refresh
├── mail/          — listThreads, getThread, reply, archive, star, markRead
├── calendar/      — listEvents, getEvent, rsvp
├── pulses/        — listPulses, getPulse
└── notifications/ — listNotifications, markRead
```

### Local Cache (Hive/Isar)
```
CachedThread    { id, subject, snippet, from, date, unread, labels }
CachedEvent     { id, title, start, end, location, status }
CachedPulse     { id, title, summary, created_at, is_quiet }
UserPrefs       { theme, notifications_enabled, selected_account_id }
```

### Riverpod Providers
```
authProvider            — AuthNotifier (token state, login/logout)
activeAccountProvider   — current account selection
mailThreadsProvider     — AsyncNotifier<List<Thread>>
threadDetailProvider(id)— FutureProvider<ThreadDetail>
calendarEventsProvider  — AsyncNotifier<List<Event>>
eventDetailProvider(id) — FutureProvider<EventDetail>
pulsesProvider          — AsyncNotifier<List<Pulse>>
notificationsProvider   — AsyncNotifier<List<Notification>>
themeProvider           — StateProvider<ThemeMode>
```

## User Flows

### 1. Login
1. User opens app → `/login`
2. Taps "Sign in to Construct" → OAuth2 browser flow
3. Receives token → stored securely (flutter_secure_storage)
4. If multi-org → org picker → navigate to `/`

### 2. Check inbox
1. Home screen loads → parallel fetch: unread mail (top 5), today's events, latest pulse
2. User taps a mail thread → `/mail/:id` → full thread loads
3. User can reply (inline composer), archive, or star
4. Pull-to-refresh on any list screen

### 3. Calendar glance
1. Tap Calendar tab → today + 7-day view
2. Tap event → detail with attendees
3. RSVP (accept/decline/tentative) sends back to Construct API

### 4. Pulse summaries
1. Tap Pulses tab → chronological list of summaries
2. Each card shows title + 2-line preview
3. Tap → full summary with links to source items (mail thread, event)

### 5. Push notifications
1. FCM token registered on login
2. Construct backend sends push for: urgent mail, upcoming events (15min), pulse results
3. Tap notification → deep link to relevant screen
