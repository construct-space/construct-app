# Plan — Live Score (football)

## Classification

New Construct Space. Single-purpose live-score dashboard for football/soccer. UI-heavy with simulated real-time updates from mock fixtures; no backend dependency, no API keys. Favorites persisted on-device.

## Identity

- **Space id**: `livescore`
- **Display name**: Live Score
- **Scope**: `app` (single-user dashboard; no shared org data)
- **Icon**: ⚽ (lucide `goal` or inline emoji)
- **One-liner**: "Live football scores, fixtures, and standings."

## Decisions locked

| Key | Value |
|---|---|
| Sport | Football / Soccer |
| Data source | Mock fixtures (adapter shape lets us swap in football-data.org later) |
| Favorites storage | `useLocalStorage` — device-local, zero backend |
| Polling | `setInterval` 5s simulated tick advances minute + occasional goal |
| Routing | Hash router (`#/`, `#/match/:id`, `#/settings`) |

## Pages

1. `/` **Dashboard** — three sections:
   - **Live now** — matches with `status === 'live'`, score + minute, red dot
   - **Today's fixtures** — upcoming kickoffs grouped by league
   - **Recent results** — last 24h finished matches
   - Filter chip row: All / Favorites / by league
2. `/match/:id` **Match detail** — scoreboard, timeline of events (goals, cards, subs), lineups stub, head-to-head stub
3. `/settings` **Settings** — favorite teams (toggle), favorite leagues (toggle), refresh cadence, "Reset favorites" button

## Data model

All in-memory + localStorage. No Graph models.

```ts
type League = { id: string; name: string; country: string; logo?: string }
type Team   = { id: string; name: string; short: string; crest?: string }
type MatchStatus = 'scheduled' | 'live' | 'half-time' | 'finished'
type MatchEvent = {
  id: string
  minute: number
  type: 'goal' | 'yellow' | 'red' | 'sub'
  team_id: string
  player: string
  detail?: string
}
type Match = {
  id: string
  league_id: string
  home_id: string
  away_id: string
  kickoff: string          // ISO
  status: MatchStatus
  minute: number           // 0..90+
  home_score: number
  away_score: number
  events: MatchEvent[]
}

// localStorage
type Favorites = {
  team_ids: string[]
  league_ids: string[]
  refresh_seconds: number  // default 5
}
```

Seed: ~6 leagues (EPL, La Liga, Bundesliga, Serie A, Ligue 1, UCL), ~24 teams, ~12 matches spread across live/scheduled/finished so every section of the dashboard has content on first render.

## Live simulation

A `useLiveClock` composable runs a `setInterval`:
- Every tick (default 5s): advance `minute` on live matches by 1
- Random chance per tick to push a goal event + bump score
- At `minute === 45` flip to `half-time`, resume at 46 after one tick
- At `minute === 90` flip to `finished`
- One scheduled match per minute promotes to `live` to keep the board fresh

Adapter shape (`src/data/source.ts`) exposes `listMatches()`, `getMatch(id)`, `subscribe(cb)` — mock impl today, real HTTP impl later behind the same interface.

## User flows

1. **Open space** → Dashboard loads with 3 live matches, 5 upcoming, 4 finished. Live dot blinks; minute increments every 5s.
2. **Tap a match** → Match detail with running event timeline.
3. **Favorite a team** → Tap star on match card → team_id added to localStorage → "Favorites" filter chip now shows that match.
4. **Settings → refresh** → Change cadence from 5s to 2s → ticks speed up.
5. **Reset favorites** → confirm modal → localStorage cleared.
