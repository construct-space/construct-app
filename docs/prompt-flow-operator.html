RUST

Tauri bridge → operator socket

›
JS invoke → Rust IPC → TCP framing to operator on :60100

Tauri's invoke() on the JS side marshals to a Rust command. The bridge connects to the local operator over TCP 127.0.0.1:60100 and writes a length-prefixed JSON request { method: "ai.chat_stream", payload: {...} }.

+ENRICH

System prompt assembly

›
Base prompt + project ctx + CLAUDE.md + memory hint + skills index

Concatenated into one system message in this order:

  • Base agent prompt — e.g. configs/coder.md body
  • Project context — working dir, active project name, repo info
  • CLAUDE.md — user + project-level instructions
  • Memory hint — recently-edited files / topics from the file tracker
  • Skills index — compact one-line per skill (NOT the full body); agent calls load_skill on demand
  • Request instructions — any system-role messages from the chat history get appended

Cache split: the static prefix (base + project + CLAUDE.md) sits before a boundary marker so providers with prompt caching (Anthropic) can hit the cache.

+ENRICH

Tool assembly

›
ForAgent (allow/block) + skill tools + sub-agent tools + spawn filter + synthetic schema

Steps in run_setup.go:169–184:

  • ForAgent(allowed, blocked) — registry filter. Default excludes space:* tools (added 2026-05-13 to fix xAI 200-tool overflow); they're opt-in via the agent's tools list.
  • addSkillTools — pulls in tools listed by skills the agent already loaded
  • addSubAgentTools — sub-agents the file tracker reports as active
  • filterSpawnTool — drops spawn_agent if the agent's canSpawn is false
  • injectDynamicSchema / InjectSyntheticOutputTool — when caller wants structured output but the model doesn't support native response_format: json_schema, we inject a tool that wraps the schema

Each tool is then OpenAI-sanitized (buildToolDefs) — name characters cleaned, schema fields normalized.

+ENRICH

Routing — coordinator vs direct

›
No separate classifier — the active agent's prompt is the router

There's no standalone "prompt classifier" service. Routing is a property of whichever agent the user picked:

  • coordinator (configs/coordinator.md, maxIterations: 50, canSpawn: true) — decides per turn whether to answer directly or call spawn_agent for a worker
  • coder / architect / verifier / ask — domain-specialized prompts, no spawning

The "decision" lives in the model's first response: if it emits a spawn_agent tool call, a child Runner.Run kicks off; otherwise the runner streams the assistant message and continues the turn loop.

CONNECTOR

Provider buildBody

›
Translates the assembled state into a wire request

Per-provider connector takes { system, messages, tools, outputSchema, maxTokens } and produces an HTTP body:

  • OpenAI-compat (DeepSeek, xAI, MiMo, Qwen, Z.ai, Kimi, OpenRouter) — flat messages, tools as functions, response_format: json_schema when schema present
  • Anthropic — separate system, content blocks for messages, prompt cache markers
  • Codex (OpenAI OAuth) — bearer = ChatGPT Plus access token
  • OpenRouter — same shape as OpenAI-compat plus model routing flags

Capabilities matter here: if the model's SupportsStructuredOutput is false (per probe matrix — DeepSeek, MiMo today), schema is NOT sent as response_format; instead the synthetic-output tool was injected upstream.

HTTP/SSE

Upstream chat completion

›
POST /chat/completions (or /v1/messages for Anthropic), streamed

Auth header set per request:

  • API-key providers: Authorization: Bearer <key> resolved via resolveKey() — env > settings.json (provider_key:<id>) > org-shared key
  • OAuth providers: live access token from profiles/<id>/providers/auth.json, refreshed on demand
  • Construct managed: live cat_* session token forwarded; gateway applies the upstream key + credit ledger

Stream body is parsed line-by-line; each data: {...} chunk is converted to a StreamEvent (text_delta, tool_call_start, tool_call_delta, done).

LOOP

Tool exec + turn loop

›
Stream events drive: emit text, run tools, feed results back, decide next turn

Per turn:

  • text_delta → forwarded as a stream chunk to UI
  • tool_call → looked up in the registry, executed (with safety hooks); result becomes a tool-role message on the next turn
  • done → if stop_reason == "tool_use", run another turn; otherwise finish

Caps: maxTurns (per agent) and hardCap = min(maxTurns*4, 500) kill runaway loops. The stuck-loop detector (stuck_loop.go) bails if the same tool runs with the same input N times.

STREAM OUT

Back through Tauri to the UI

›
Every event reverses the path — operator → Rust → JS → Vue render

Each stream chunk emitted by the runner is sent back over the same TCP connection, repackaged by Rust as a Tauri event, picked up by the JS client, and dispatched into the Pinia chat store. The composer renders incremental tokens, tool cards, and final messages.
